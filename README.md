# FitCollector

Сервіс для пошуку **найдешевшого білка та калорій** у польських магазинах і складання **денного раціону за мінімальну ціну** під задані КБЖВ.

Жодних вигаданих даних: ~1100 продуктів з реальними цінами й фото, з них ~300 з повною КБЖВ — саме вони беруть участь у білкових метриках та оптимізаторі.

## Звідки дані

| Джерело | Що дає |
|---|---|
| **zakupy.biedronka.pl** (скрапер) | ~950 продуктів Biedronka: офіційна актуальна ціна, фото, назва, бренд, категорія. Обхід усіх харчових категорій з пагінацією (`?page=N&format=page-element` — той самий механізм, що юзає їхній infinite scroll) |
| **Open Prices** | Краудсорсні ціни з чеків для решти мереж: Lidl, Kaufland, Carrefour, Netto, Dino, Auchan… |
| **Open Food Facts** | КБЖВ на 100 г: для Open Prices — по штрихкоду; для Biedronka (сайт не публікує ні КБЖВ, ні EAN) — матчинг по (вага упаковки, бренд, токени назви) проти індексу популярних польських продуктів |

Все кешується на диску (`data/`): каталог — 24 год, OFF-індекс і КБЖВ — 7 днів. Оновлення йде у фоновому потоці, прогрес видно в шапці UI. Вбудований снапшот (`catalog-snapshot.json`) робить перший запуск миттєвим і офлайн-здатним. Примусове оновлення — кнопка «Оновити ціни» або `POST /api/refresh`.

## Що вміє

- Каталог з фото, пошуком без діакритики (`platki` знайде `Płatki`), фільтрами по магазинах/категоріях і сортуванням: zł за 100 г білка, zł за 1000 ккал, білок/ккал за 1 zł.
- «Раціон дня»: цільові ккал + мінімум білка (+ опційні ліміти жирів/вуглеводів) → найдешевший набір продуктів через лінійне програмування (симплекс, задача Стіглера). Сировина типу борошна й цукру виключена — інакше оптимум чесно радить їсти сире борошно. День на 1200 ккал / 90 г білка виходить ~3.5 zł.
- Продукти без відомої КБЖВ лишаються в каталозі (ціна й фото реальні), але не беруть участі в білкових метриках і раціоні; при сортуванні йдуть у кінець.

## Запуск

Потрібні Java 21 і Maven.

```bash
mvn spring-boot:run
```

Відкрий http://localhost:8080

## API

| Метод | Шлях | Опис |
|---|---|---|
| GET | `/api/products?store=Biedronka&category=крупи&q=kasza&sort=pricePer100gProtein&order=asc` | Каталог. `sort`: `pricePer100gProtein`, `pricePer1000Kcal`, `proteinPerZloty`, `kcalPerZloty`, `pricePer100g`, `price`, `name` |
| GET | `/api/stores`, `/api/categories` | Значення для фільтрів |
| GET | `/api/status` | Розмір каталогу + стан фонового збору |
| POST | `/api/refresh` | Запустити повне оновлення у фоні |
| POST | `/api/ration` | Скласти найдешевший раціон |

```bash
curl -X POST http://localhost:8080/api/ration \
  -H 'Content-Type: application/json' \
  -d '{"targetKcal":1200,"minProteinG":90,"maxFatG":null,"maxCarbsG":null,"stores":[],"maxGramsPerProduct":400}'
```

## Конфігурація (`application.properties`)

| Властивість | Типово | Що робить |
|---|---|---|
| `fitcollector.data-dir` | `./data` | Куди складати кеші |
| `fitcollector.catalog-ttl-hours` | `24` | Свіжість каталогу |
| `fitcollector.stores` | Lidl, Kaufland, … | Мережі з Open Prices (Biedronka йде зі скрапера) |
| `fitcollector.biedronka.throttle-millis` | `400` | Пауза між сторінками скрапера |
| `fitcollector.off.index-popular-pages` / `index-store-pages` | `20` / `15` | Розмір OFF-індексу для матчингу |
| `fitcollector.ration.exclude-terms` | mąka, cukier, … | Сировина, виключена з раціону |

## Архітектура

```
BiedronkaClient ──┐  плитки: назва, бренд, ціна, фото, категорія
                  ├─→ OffMatchIndex.match(вага, бренд, назва) → КБЖВ
OpenPricesClient ─┤  ціни з чеків інших мереж
                  ├─→ OpenFoodFactsClient (КБЖВ по штрихкоду, кеш 7 дн)
                  ▼
CatalogIngestionService → data/catalog.json (TTL 24 год) → CatalogService → API
                                                            RationOptimizer (симплекс)
```
