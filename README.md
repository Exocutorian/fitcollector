# FitCollector 🥦

Сервіс для пошуку **найдешевшого білка та калорій** у польських магазинах і складання **денного раціону за мінімальну ціну** під задані КБЖВ.

Дані — **реальні**: ціни тягнуться з краудсорсної бази [Open Prices](https://prices.openfoodfacts.org/) (сфотографовані чеки й цінники з Biedronka, Lidl, Kaufland, Carrefour, Netto та інших польських мереж), КБЖВ і фото продуктів — з [Open Food Facts](https://world.openfoodfacts.org/) за штрихкодом. Плюс локальна seed-база як доповнення для позицій, яких ще немає в краудсорсі (позначаються «≈ орієнтовна»).

## Що вміє

- 📊 Каталог продуктів з фото, реальними цінами та метриками:
  - 💪 zł за 100 г білка;
  - 🔥 zł за 1000 ккал;
  - 💰 грамів білка / ккал за 1 zł.
- Пошук (без урахування діакритики: `platki` знайде `Płatki`), фільтри по магазинах і категоріях, сортування по будь-якій метриці.
- 🍱 «Раціон дня»: вводиш цільові ккал, мінімум білка, (опційно) максимум жирів/вуглеводів — сервіс через лінійне програмування (симплекс-метод, класична задача Стіглера) підбирає найдешевший набір продуктів. День на 1200 ккал / 90 г білка виходить за ~5–13 zł залежно від обмежень.

## Запуск

Потрібні Java 21 і Maven.

```bash
mvn spring-boot:run
```

Відкрий http://localhost:8080 — каталог працює одразу (вбудований снапшот), а у фоні автоматично підтягуються свіжі ціни.

## Як влаштований збір даних

```
Open Prices (ціни в PLN, постранично)
        │  фото цінників/чеків від користувачів: код, ціна, дата, магазин (osm_brand),
        │  вбудований OFF-продукт: назва, бренд, вага упаковки, картинка, категорії
        ▼
CatalogIngestionService — найсвіжіша ціна на пару (штрихкод, мережа)
        │
        ▼
Open Food Facts /api/v2/product/{code} → КБЖВ на 100 г
        │  (тротлінг під ліміт OFF, дисковий кеш 7 днів: data/off-nutriments/)
        ▼
Валідація (правдоподібність ваги/ціни/калорій) → data/catalog.json (TTL 24 год)
        │
        ▼
CatalogService = реальні продукти + seed-база (products.json)
```

- Перший запуск працює миттєво завдяки вбудованому снапшоту (`catalog-snapshot.json`).
- Кеш застарів → оновлення стартує автоматично у фоні (перевірка щогодини), прогрес видно в шапці UI і в `GET /api/status`.
- Примусове оновлення: кнопка «⟳ Оновити ціни» або `POST /api/refresh`.
- Ціна «за кілограм» (вагові товари) перераховується на упаковку автоматично.

## API

| Метод | Шлях | Опис |
|---|---|---|
| GET | `/api/products?store=Lidl&category=молочка&q=twarog&sort=pricePer100gProtein&order=asc` | Каталог. `sort`: `pricePer100gProtein`, `pricePer1000Kcal`, `proteinPerZloty`, `kcalPerZloty`, `pricePer100g`, `price`, `name` |
| GET | `/api/stores` | Магазини |
| GET | `/api/categories` | Категорії |
| GET | `/api/status` | Розмір каталогу + стан фонового збору |
| POST | `/api/refresh` | Запустити оновлення цін у фоні |
| POST | `/api/ration` | Скласти найдешевший раціон |

Приклад запиту раціону:

```bash
curl -X POST http://localhost:8080/api/ration \
  -H 'Content-Type: application/json' \
  -d '{"targetKcal":1200,"minProteinG":90,"maxFatG":null,"maxCarbsG":null,"stores":[],"maxGramsPerProduct":400}'
```

## Конфігурація (`application.properties`)

| Властивість | Типово | Що робить |
|---|---|---|
| `fitcollector.data-dir` | `./data` | Куди складати кеші |
| `fitcollector.catalog-ttl-hours` | `24` | Свіжість каталогу цін |
| `fitcollector.stores` | Biedronka, Lidl, … | Мережі, які беремо з Open Prices |
| `fitcollector.off.throttle-millis` | `700` | Пауза між запитами до OFF |
| `fitcollector.open-prices.max-pages` | `30` | Скільки сторінок цін тягнути |

## Як працює оптимізатор

Змінні — кількість кожного продукту (в одиницях по 100 г). Мінімізується сумарна вартість за умов:

- калорії ≥ ціль і ≤ ціль + 5 % (щоб раціон не «роздувався» дешевими калоріями);
- білок ≥ мінімум;
- жири/вуглеводи ≤ максимум (якщо задано);
- не більше N грамів одного продукту (для різноманітності).

Розв'язується симплекс-методом (`commons-math3`). Порції округлюються до 5 г, дрібніші за 15 г — відкидаються.
